# Agent instructions — Marketing OS

Instructions for ANY AI coding agent (Kimi, Claude, or other) working in this repository.

## What this repo is

A complete customer-acquisition + marketing engine for **InfraSync, a D2C apparel & footwear
brand** (clothing, shoes, bags & accessories — innerwear sold but never advertised), built
entirely on free and open-source tools. Hard overhead cap: **₹0–100/month** (per-order costs
like payment fees, shipping, and WhatsApp order updates are cost of goods). All strategy is
already decided and documented — agents execute the plan; they do not redesign it.

## Read before doing anything

0. `knowledge/context.md` — the 1-page situation report (then `knowledge/handoff.md` for the start/end-of-session protocol)
1. `README.md` — the rules of the build and the build-status checklist
2. `BUILD-LOG.md` — what has already been done (never redo logged work)
3. `plan/00-stack.md` … `plan/06-operate-and-scale.md` — the stage guide, in order
4. `workflows/` — recurring procedures once the build is operating
5. `agent/offers.md` — the ONLY source of business facts (catalog, prices, offers, policies, claims rules); `PIPELINES.md` — the one-page map

## How to work

Follow the operating loop in **`prompts/build-loop.md`** for every iteration: one task,
finished completely, verified, checkbox ticked, logged to `BUILD-LOG.md`, reported —
then ask the user if they want anything changed before the next iteration.
(In Claude Code the same loop is the `/marketing-loop` command.) Start and end every session per
`knowledge/handoff.md`; when a decision, tool, or the overall picture changes, update
`knowledge/decisions.md` / `knowledge/tooling.md` / `knowledge/context.md`. Git is ON: commit
after every verified task; never commit `.env`.

## Non-negotiable rules

- **Never spend money on overhead.** No paid tiers, no upgrades, no "it's only $5". Spending
  requires a documented trigger in `plan/06-operate-and-scale.md` plus explicit user approval.
- **Never send anything to a real person** (email, WhatsApp, social post, DNS change) or
  publish a product/price change without explicit user approval for that action.
- **Official WhatsApp Cloud API only.** Unofficial clients (Evolution API, WAHA, Baileys)
  must never be connected to the company's number.
- **Ask, don't guess** on business facts, credentials, and anything ambiguous. Secrets go in
  `.env` files (git-ignored), filled in by the user — never pasted into chat, never committed.
- **Verify before claiming done.** Untested work is not done and its checkbox stays unticked.
- Stay within the stack defined in `plan/00-stack.md`; propose swaps to the user instead of
  making them silently.

## Brand & compliance rules (apply to every generated word and image)

- The product shown is always the **real product** — real photos as references; no invented garments.
- No fake reviews/testimonials, no fake scarcity or countdowns, discounts only against real prior prices.
- **Innerwear never appears** in ads, social posts, or email subject lines.
- AI-generated people are models/hosts — never presented as customers.
- Mandatory e-commerce disclosures (returns, shipping, seller details, country of origin, MRP) must exist before payments go live.

## Environment notes

- Target machine: Windows 11, RTX 5070 12GB, 32GB RAM (research, FFmpeg joins, captions — no local video generation).
- Ads are generated by the USER in Google Flow (no API); agents prepare briefs/prompts before and join/publish after.
- Server: Oracle Cloud Always-Free ARM VM (Ubuntu, Docker) — created by the user, Stage 2 — hosts Medusa, Listmonk, Postiz.
- Free LLM keys for runtime features (not for you): NVIDIA NIM, Groq, Gemini — router spec
  in `plan/05-agent-automation.md`.
